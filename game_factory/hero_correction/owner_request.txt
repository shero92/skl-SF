## 6. WEAPON ATTACHMENT POINTS

For EVERY battle animation frame, create weapon attachment metadata.

Required:

- character_id
- animation_name
- frame_index
- hand_anchor_x
- hand_anchor_y
- hand_rotation_degrees
- weapon_scale
- weapon_render_order
- grip_type

Create:

`hero_weapon_anchors.json`

The hand anchor must correspond to the actual grip location in each individual frame.

The weapon must move naturally with the Hero's hand throughout the animation.

Do not use one fixed attachment position for every frame.

The attachment must support:

- Translation
- Rotation
- Optional scale adjustment
- Front/behind-body rendering

Use appropriate pivot positions so the weapon grip remains aligned to the hand.

Where necessary, split character rendering into front and back components to support correct weapon occlusion.

Do not place weapons randomly over the character image.

---

## 7. GODOT BATTLE RENDERING

The battle character should use separate rendering components.

Suggested structure:

BattleCharacter
    BodySprite
    WeaponBack
    WeaponFront
    Effects

Use data-driven animation frame metadata to update the equipped weapon transform.

For each frame:

1. Load the Hero's weaponless body image.
2. Read the hand anchor.
3. Load the equipped weapon PNG.
4. Position its grip pivot at the hand anchor.
5. Rotate it according to the attack pose.
6. Render the weapon at the correct depth.
7. Display attack effects independently.

The same Hero body animation must support changing swords at runtime.

Changing the equipped sword must NOT require generating a new Hero sprite.
