## قرار المالك

- Codex مسؤول عن التحليل والتقارير وصياغة المهام وتوليد الصور والأصول ومراجعتها بصرياً؛ لا يكتب أو يعدّل الكود أو الاختبارات أو إعدادات الأتمتة.
- Aider مسؤول عن البرمجة العادية. يلتقط فقط المهام الجاهزة والمسنَدة إليه صراحة، بعد تحقق تبعياتها.
- Claude Code مسؤول عن البرمجة المعقدة عند طلب المالك صراحة إنشاء مهمة له. التوصية باستخدام Claude لا تُعد إسناداً أو إذناً بتشغيله.
- لا يحوّل Codex أو المشغّل مهمة متعثرة إلى Claude تلقائياً.
- توليد الصور لا ينتقل إلى Aider، والأصول المعتمدة لا تُستبدل تلقائياً.

## سير العمل المطلوب بعد تنفيذ الربط

1. عند طلب إنشاء مهمة، يصوغ Codex النتيجة ونطاق الملفات والتبعيات واختبارات القبول، دون تنفيذ الكود.
2. المهمة العادية الجاهزة تُسنَد إلى Aider في سجل TASK القائم. لا ينشأ طابور مستقل ينافس مصدر الحقيقة الحالي.
3. مراقب Windows يفحص الطابور كل 10 ثوانٍ، بعامل واحد وقفل يمنع تكرار الاستلام. المهمة غير الجاهزة أو غير المسندة إليه لا تبدأ.
4. كل مهمة تنفذ في branch وworktree معزولين، بإعداد النموذج الحالي وطلب غير تفاعلي من ملف. المشغّل يتولى الاختبارات والحفظ والدمج، ولا يعتمد على جلسة Aider التفاعلية المفتوحة.
5. يتوقف دمج المهمة إذا خرجت عن نطاق الملفات، فشلت الاختبارات أو ظهر تعارض. تحفظ أدلتها وتُحظر مع السبب؛ تستمر المهام المستقلة المؤهلة.
6. الدمج تلقائي مشروط وتسلسلي بعد تحديث الفرع والاختبارات، ثم تحقق بعد الدمج. عند فشله، يُرجع دمج المهمة نفسها، وتُمنع عمليات الدمج التالية حتى معالجة السبب.
7. يبقى المراقب منتظراً عند فراغ الطابور. رغبة المالك هي استمرار العمل دون حد يومي اختياري للمهام أو الإنفاق؛ لا تعني تجاهل نفاد الرصيد أو أخطاء الاعتماد أو حدود الخدمة، ولا تبديل النموذج تلقائياً.
8. أخطاء الخدمة المؤقتة: ثلاث إعادات بتأخير 30 ثم 60 ثم 120 ثانية. إصلاح اختبار المهمة: محاولتان، ثم حظرها إذا لم تنجح. تسجل النتائج والاستهلاك المتاح؛ القيم المجهولة لا تُختلق.
9. تعطيل التشغيل يوقف التقاط مهام جديدة، ولا يحذف عملاً جارياً. إعادة التشغيل تصالح حالة المهمة قبل تشغيل نسخة أخرى منها.

## الخطوات التالية بالترتيب

1. مطابقة الملفات المحلية والفروع وسجلات الأصول، وفصل المنجز التقني عن الاعتماد البصري. لا دمج جماعي للتغييرات القائمة.
2. عند طلب المالك الصريح فقط: إنشاء مهمة Claude Code لتنفيذ ربط Aider. سبب التعقيد: تعديل التوجيه والمراقبة والأقفال والعزل والدمج والتعافي وتسجيل المنفذ، مع الحفاظ على عمل المستخدم.
3. ينفذ Claude مهمة البنية على فرع مستقل وتُراجع؛ لا تُفعّل الأتمتة بمجرد تعديل مستند أو إعداد.
4. تنفيذ اختبار مراقَب: إنشاء مهمة صغيرة جاهزة لـAider، التقاطها مرة واحدة، تعديل معزول، اختبارات، commit، دمج وتحقق لاحق. اختبار التوقف وإعادة التشغيل والفشل والتعارض وعدم لمس الصور أو تغييرات المستخدم.
5. بعد نجاح الاختبار وتفعيل المشغّل المسؤول: إنشاء مهام Aider العادية حسب الأولوية والتبعيات.
6. اختيار أسلوب هجوم Hero بصرياً، ثم يتولى Codex إنتاج أصوله؛ تُنشأ مهام Aider لدمج الأصول المختارة برمجياً.
