Build a complete automated pixel-art asset production pipeline for my local Godot project "skl-SF".

GOAL:
Generate a full high-quality modular asset library from the fantasy room reference, with every tile and every object produced as a separate individual image file, properly named and organized into folders, ready for direct use in Godot Map Factory.

IMPORTANT OVERALL RULE:
- Every asset must be generated as a separate standalone PNG.
- Never generate multiple different assets inside one image.
- Never generate a collage, contact sheet, sprite atlas, comparison sheet, or labeled overview image.
- One asset = one prompt = one PNG file.

PROJECT CONTEXT:
This project is a fantasy tactical RPG inspired by classic Shining Force style.
The room reference defines the visual target:
- warm golden sandstone floor
- ruined pale stone walls
- blue-and-gold cloth decorations
- wooden fantasy furniture
- lush flowers, vines, and plants
- bright ocean-cliff environment
- premium hand-crafted pixel-art quality

VISUAL STYLE REQUIREMENTS:
- Premium high-quality 2D pixel art.
- Crisp pixel edges.
- No blur.
- No smoothing.
- No anti-aliasing.
- No modern vector look.
- No painterly soft rendering.
- No 3D model appearance.
- No photorealism.
- Strong readability at game scale.
- Rich but controlled detail.
- Consistent materials, colors, and lighting across all assets.

CAMERA / PERSPECTIVE REQUIREMENTS:
- Use the room reference as the strict perspective guide.
- The floor is a square grid facing the player.
- This is NOT a diamond isometric 2:1 map.
- Use a square-grid, player-facing, top-down / 3/4 RPG room perspective.
- All floor tiles must align to a square grid.
- All furniture must sit correctly on this square floor grid.
- All assets must match the same camera direction.

LIGHTING REQUIREMENTS:
- Warm sunlight / ambient light from upper-left.
- Subtle shadowing toward lower-right.
- Consistent lighting direction across all assets.
- No dramatic inconsistent lighting.
- No detached cast shadows outside the intended sprite area unless explicitly required.

BASE SCALE RULES:
- Standard floor tile size = 64x64 pixels.
- Standard wall block footprint = 1x1 tile unless otherwise specified.
- Large objects can occupy multiple tiles.
- Every asset must explicitly define:
  1. asset ID
  2. asset name
  3. category
  4. native art resolution
  5. ground footprint in tiles
  6. orientation
  7. anchor point
  8. whether transparency is required
  9. whether it is floor / wall / overlay / furniture / decor / background

CRITICAL FILE OUTPUT RULES:
- Save every asset as an individual PNG.
- Use transparent background for objects, props, walls, decor, furniture, plants, banners, lamps, architecture pieces, and overlays.
- Floor tiles may be opaque or transparent depending on pipeline preference, but individual tile files are required.
- Do not include labels, text, checkerboards, watermarks, borders, or UI.
- Do not embed multiple assets in one image.
- Do not crop important parts.
- Do not leave excessive empty padding.

NAMING RULES:
Use the following output naming convention:

[ASSET_ID]__[CATEGORY]__[ASSET_NAME]__[ORIENTATION]__[FOOTPRINT]__[SIZE].png

Examples:
G01__floor__clean_sandstone__south__1x1__64x64.png
F01__furniture__royal_bed__south__3x4__192x256.png
W03__wall__broken_stone_wall__south__1x1__64x64.png
A05__architecture__central_arch_column_left__south__1x1__64x128.png

If the asset has no meaningful orientation, use:
__default__

If the object has directional variants, generate each direction as a separate asset:
__south__
__west__
__north__
__east__

ASSET QUALITY RULES:
Each asset must:
- be readable at intended game scale
- preserve pixel-art integrity at native size
- maintain stylistic consistency with reference
- fit correctly on the square floor grid
- respect the specified footprint
- avoid excessive noise
- avoid muddy texture
- avoid repeated visible artifacts unless intentionally designed
- look like a real premium game asset

NO CHARACTER RULE:
Do not generate player characters, NPCs, monsters, or pets yet.
Focus only on environment assets and modular room-building assets.

ROOM-BUILDING / MAP FACTORY RULES:
All assets must be suitable for procedural or factory-based room assembly in Godot.
That means:
- clear modularity
- clean footprint logic
- consistent anchor positions
- correct layering
- separable objects
- reusable blocks
- directional consistency
- repeatable floor tiles
- wall blocks that connect naturally
- architecture pieces that can be assembled into larger structures

LAYERING RULES:
Every asset must belong to one of these layers:
- background
- ground
- wall_base
- wall_overlay
- furniture
- decor
- lighting
- foliage
- prop_overlay

Use layering logic that allows Godot Map Factory to assemble the room correctly.

FOOTPRINT LOGIC:
The image size and the object footprint are not the same thing.
For example:
- a floor tile may be 64x64 and footprint 1x1
- a bed may visually be 192x256 with footprint 3x4
- a bookcase may visually be 256x128 with footprint 4x1
- an arch pillar may visually be 64x128 with footprint 1x1

Always preserve both:
1. visual sprite size
2. logical footprint

DIRECTIONAL RULES:
For all furniture and relevant objects that need rotation:
- generate four real directional redraws
- do not just rotate the same image mechanically
- keep material, color, proportions, and identity identical
- each direction must be a separate file
Directions:
- south
- west
- north
- east

REFERENCE PRIORITY:
Use the original room image as the primary style, composition, material, and color reference.
Use approved individual assets as secondary references for consistency.
If an approved tile exists, new similar assets must match it closely.

PRODUCTION WORKFLOW:
1. Read the asset list.
2. Generate one asset at a time.
3. Save PNG and JSON metadata.
4. Validate dimensions.
5. Validate transparency when required.
6. Validate filename and folder placement.
7. Generate preview tests when needed.
8. Mark asset as approved or failed.
9. Never overwrite an approved asset unless explicitly instructed.

AUTOMATED VALIDATION RULES:
After generation, validate:
- correct file dimensions
- correct naming format
- correct folder placement
- presence of transparency where required
- correct footprint metadata
- no labels or collage layout
- one asset only per file

Additionally:
- For floor tiles: create repeat preview tests (5x5 and 10x10)
- For wall tiles: create adjacency preview tests
- For furniture: create placement preview test on a floor grid
- For multi-direction assets: create direction consistency preview

APPROVAL RULE:
Only approved assets move to /approved/.
Rejected or problematic assets go to /failed/ with notes.
